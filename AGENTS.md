# Project architecture rules
- Email-field admin shortcuts navigate to protected sign-in only; never grant privileges or replace server verification. Why: convenience must not expose administrative records.
- Entry and idle share EntryPassGlobe; idle opacity, tint and framing are scoped, never saved. Why: avoid star bleed and cropping without changing entry or dashboard choices.
- ShareQrCode preserves finder patterns, central branding, high correction, outer glow and quiet-zone PNG exports. Why: protect scanning and motion accessibility.
- Crypto credits require server authorization, matching verified receipts and merchant reconciliation; credit idempotently. Why: unpaid calls/retries cannot grant access.
- Admin finance uses server-verified guards and stable paginated allowlisted queries matching overview filters; mark accepted requests unconfirmed. Why: protect records without changing balances.
- Retain request deliveries in a separate private bucket; creator cleanup archives, never deletes customer media. Payment/delivery fields remain server-managed with expiring customer access. Why: agreement is not payment.
- Renew requests/subscriptions atomically, locking balances/access and preserving ledger splits; reject duplicate cycles. Subscription renewal is service-only with expected-expiry checks. Why: prevent double charges/partial earnings.
- Aggregate complete account-scoped earnings server-side in UTC; paginate history and scope/coalesce realtime. Why: avoid truncation and refresh storms.
- Welcome-back reads only account-scoped completed ledger rows; admin samples never write them. Why: preserve real earnings.
- Auth callbacks use DTT; Google uses the initiating origin off live hosts, with the generated Cloud helper and owner credentials. Why: branded sign-in returns to its originating window.
- Profiles are owner/admin-only; public_profiles is a safe read-only projection; photo writes require folder/object ownership. Why: prevent identity leaks and cross-account edits.
- Use ProfileAvatar for private identities.
- Validate avatar colors; use iro wheels/SVG fills. Why: safe customization.
- Generate role-specific portraits server-side from in-memory selfies; never retain originals; portraits stay account-private. Why: protect identity.
- Creator real photos stay in owner-owned private galleries; discovery shows selected photos, private interactions the emoji. Why: separate identities.
- Bound in-page selfies, release tracks, skip scans. Why: avoid handoffs/WASM.
- Prebundle pickers with deduped React. Why: avoid mixed hooks.
- Permanently watermark all new creator photos/videos through the shared encoder before storage; fail closed, excluding IDs/customer selfies. Why: display overlays do not brand downloads.
- CCBill uses signed forms, private/IP-restricted notices and idempotent catalog credits. paymentReadiness requires DTT_<PROVIDER>_LIVE_APPROVED/CHECKOUT_VERIFIED flags and credentials. Why: keys do not prove approval.
- Creator uploads require owner role and latest audited adult-ID approval with reviewer confirmation; IDs/avatars stay separate. Why: manual review must not permit self-approval.
- Only the CCBill server webhook applies handle_chargeback bans in account_bans; admins lift through admin_lift_ban. Why: user-editable profiles cannot control lockouts.
- AutoTranslator merges source-matched public/ui/launch catalogs before member-only AI; long public policies use saved translations only; bound caches/retries and coalesce misses; owner/code and input values stay unchanged. Why: protect private text and avoid repeated translation spend.
- Keep a native-name language selector above entry, region checks, and every routed page. Why: visitors must be able to select a readable language before paying or signing in.
- Publish trigger-maintained heart totals, never public fan rows; social/analytics subscribe to aggregates. Why: update counts without exposing identities.
- Account-owned teasers retain frames/activation windows; select one active item atomically through an owner-validated function, falling back to latest after expiry. Why: consistent selection and permanent branding.
- Snapshot request country at creation; preserve on updates. Why: privacy.
- GeoGate fails closed, no local overrides; not server enforcement.
- Search/library/feed gender visibility follows persisted explicit preferences, never infers Both from absent active vault. Why: respect filtering.
- Share studio/feed artwork and persist language countdown across reloads. Why: continuous transitions.
- Chats reuse TopFansSection with scoped messages/safe public identities. Why: protect private threads.
- Personal colors use validated ui_theme and blended renderers; idle skies inherit the galaxy unless overridden; dashboard skies never alter public profiles. Save galaxy independently of identity validation; report sync failures. Why: invalid handles must not block colors.
- Dashboard twinkling stars use separate validated ui_theme opt-in and tone with bounded canvas particles and reduced-motion support. Why: private dashboard effects must not replace globe/idle defaults or flash the whole screen.
- Only receipt-verified service mark_custom_request_paid sets paid; block other paid/completed moves. Creator-owned calendar plans/reminders never change deadlines; agreements await payment, which starts 48-hour delivery. Why: plans cannot authorize access.
- Page search/media reads; refresh authorized links no later than access expiry. Why: bound downloads and prevent stale access.
- Shared resumable uploads accept already-watermarked files; failed registration cleans staging or reports failure. Why: interruptions cannot silently succeed.
- Recover via Cloud exports plus separate Storage downloads; rehearse only in isolation; media vendors need written content approval. Why: snapshots omit files.
- Subdirectories have their own AGENTS.md; read it before changing files there.
- Founding splits use permanent approval slots; both admin views share empty-market lists. Why: vacancies never alter awards.

- Sky photos preload with stars and resume/online retries. Why: prevent broken-image borders.
- Discovery renders category shelves from the paginated authorized teaser feed; persist only bounded account/market-scoped scroll coordinates and interest counts, never signed links, and require explicit playback gestures. Why: preserve privacy and prevent autoplay.
- Library availability uses an authorized aggregate backed by existing private objects; unlock_creator rejects empty libraries before charging. Why: do not sell absent content or expose storage paths.
- Legal pages and footer reuse canonical policy sections. Why: avoid conflicting translated retention, payment and recordkeeping claims.
- Fullscreen teasers portal into document.body. Why: transformed avatars otherwise confine playback.
- Admin previews require an account session for media, never just a passcode. Normal login clears previews; account changes reset navigation. Why: protect media and prevent wrong dashboards.
- Dormant idle ships keep validated themes, reduced motion and inquiry links, no external ads. Why: safe reuse, no booked-sponsor claims.
- Profile backdrops: server-owned choices/private uploads; selected creator files member-readable; re-encode, gate/brand creator uploads. Shared bundled motion stays behind portraits, pauses offscreen, honors reduced motion; uploads stay still. Why: privacy and bounded bandwidth.
- Tip/request dialogs use body portals and bounded scrolling. Why: keep controls above navigation.
- VIP inventory reads require the server-verified creator role; inventory writes remain service-only. Why: dashboard previews must not expose counter records publicly.
- Revenue terms/countdowns use account-scoped server RPCs; request-share triggers overwrite unpaid client amounts and freeze paid earnings. Why: UI estimates cannot authorize payouts or rewrite history.
- VIP grants require service-verified receipts and a locked inventory counter; safe badge/priority RPCs expose no payment or identity details. Why: prevent unpaid upgrades, overselling and discovery data leaks.
